# Working on TabBuddy

Be direct. Do not flatter the user or trade accuracy for agreement. Avoid using “shape” and “quietly” to describe things.

Read `PROJECT.md` for current features, product intent, storage contracts, and known limitations. Keep it up to date in the same commit as feature or behavior changes. Update `README.md` for user-facing workflow changes, `DESIGN.md` for interface decisions, and `PROGRESS.md` with dated implementation and validation notes. Historical progress entries and unchecked design proposals are not proof of current behavior.

Preserve user data, library identity, store URLs, and registered signing identifiers. Test changes to imports, storage migration, offline access, and sync boundaries. Never describe simulated iCloud tests as live two-device verification. Keep downloaded song arrangements out of commits; preserve bundled third-party license notices.
